# PRIVACY / ABUSE SPEC (초안 — 법률 검토 전)

> **지위**: `docs/POLICY.md §11.9`가 위임한 하위 문서다.
> POLICY는 "기술적 어뷰징 신호를 활용할 수 있다"까지만 정하고, **무엇을 수집·보관할지는 이 문서가 정한다.**
>
> **이 문서는 초안이다.** 아래 내용은 실제 운영 전 **현지 법률 검토와 대표 승인**을 거쳐야 한다.
> 적용 법령과 의무의 해석은 **법률 자문으로 확인해야 하며, 이 문서의 판단으로 갈음하지 않는다.**
>
> **적용 법령 (2026-08 기준 · 자문으로 재확인 필요)**
> - 베트남 **개인정보 보호법 Law No. 91/2025/QH15** (2025-06-26 통과, **2026-01-01 시행**)
>   및 시행령 **Decree No. 356/2025/ND-CP**
> - ~~Decree 13/2023/ND-CP~~ 는 **2026-01-01자로 효력이 종료**되었다. 이 문서 초판이 인용했던
>   법령이므로, 과거 자료를 참고할 때 주의한다.
> - 한국 **개인정보 보호법**의 역외 적용 여부는 별도 확인 대상이다.
>
> 자문에 넘길 질문은 `docs/LEGAL_REVIEW_REQUEST.md`에 정리했다.

## 1. 원칙

1. **최소 수집** — 어뷰징 판별에 실제로 쓰이지 않는 값은 수집하지 않는다.
2. **목적 제한** — 어뷰징 판별로 수집한 값을 마케팅·랭킹·추천에 재사용하지 않는다.
   특히 **Consumer First Ranking에 절대 유입되지 않는다** (POLICY §1 · §11.5).
3. **보관 기간 한정** — 목적을 달성하면 지운다. 무기한 보관하지 않는다.
4. **접근 통제** — 원본 신호 조회는 Admin SUPER 권한 + 감사 로그 (POLICY §3의 4-eyes 원칙 준용).
5. **설명 가능성** — 자동 조치(숨김·제한)를 받은 사용자에게 사유와 이의 제기 경로를 알린다.

## 2. 어뷰징 신호 (수집 후보 — 확정 아님)

| 신호 | 판별 목적 | 제안 보관 | 검토가 필요한 이유 |
|---|---|---|---|
| 계정 ID · 게시 시각 | 단시간 대량 게시 | 90일 | 개인정보 해당. 보관 기간 근거 필요 |
| 게시물 유사도(해시) | 동일 문구 반복·도배 | 90일 | 본문 원문 대신 해시만 보관할 수 있는지 |
| 디바이스 식별자 | 다중 계정 생성 | **미정** | 식별자 종류·재설정 가능성에 따라 법적 성격이 달라짐 |
| IP 주소 | 조직적 어뷰징 | **미정** | 다수 관할에서 개인정보로 취급. 수집 자체를 재검토 |
| 신고 누적 수 | 우선 검토 대상 선별 | 180일 | 신고자 익명성 보장 방식 필요 |
| 매장-작성자 관계 | 대가성·자기 홍보 게시 (§11.7) | 90일 | 파트너 계정 연결 정보의 취급 |

> **디바이스 식별자와 IP는 이번 단계에서 수집하지 않는 것을 기본값으로 둔다.**
> 필요성이 입증되고 법률 검토를 통과한 뒤에 추가한다. "일단 모아두고 나중에 판단"은 하지 않는다.

## 3. 신고 처리 흐름 (POLICY §11.8)

```
신고 접수 → 즉시 숨김(신고자 화면) → Admin 큐 등록(사유·시각 기록)
        → 검토 → ① 복원  ② 비공개 유지  ③ 계정 제한
        → 작성자에게 결과와 이의 제기 경로 통지
```

- **즉시 숨김은 신고자 화면 기준이다.** 신고 하나로 전체 노출을 내리면 신고가 공격 수단이 된다.
  전체 비공개는 검토를 거친다.
- 차단(block)은 순수 개인 설정이며 상대에게 알리지 않는다. 언제든 해제할 수 있다.
- 내 글 삭제는 즉시 반영한다. 단 신고 검토 중인 글은 기록을 보존한다(노출은 중단).

## 4. 현재 구현 상태 (프로토타입)

| 항목 | 구현 |
|---|---|
| 신고 | 로컬 숨김 + 안내 토스트 |
| 차단 | 작성자 단위 로컬 숨김 · 해제 가능 |
| 삭제 | 내 글만 · 되돌리지 않음 |
| 신호 수집 | **없음** — 서버가 없으므로 아무것도 전송·수집하지 않는다 |

브라우저 `localStorage`에 저장하는 값은 **`{ onboarded, lang, zoneIdx }` 셋뿐**이다
(`MasterUI.jsx`의 `writeSaved`). 온보딩 완료 여부 · 화면 언어 · 선택한 생활권이며,
**개인을 식별할 수 있는 값은 없다.** 게시물 · 예약 · 적립은 새로고침하면 사라진다.

## 5. 미결 사항 (법률 검토 필요)

전체 목록과 자문용 사실관계는 **`docs/LEGAL_REVIEW_REQUEST.md`**에 있다. 요약하면:

| # | 쟁점 | 왜 시급한가 |
|---|---|---|
| 1 | Law 91/2025 적용 범위 (역외 적용) | 한국 조직이 베트남 이용자에게 서비스한다 |
| 2 | **국외 이전 영향평가(CTIA) 제출 의무** | Supabase 리전 선택에 따라 **최초 이전 후 60일 내** 제출 의무가 발생할 수 있다 |
| 3 | **건강 데이터의 민감정보 해당 여부** | Habit 걷기가 HealthKit/Google Fit 연동 예정이다 |
| 4 | 동의 획득 UX 설계 | 온보딩 화면 구조가 바뀔 수 있어 **개발 전에** 알아야 한다 |
| 5 | IP·기기 식별자 수집 근거 | 현재 "수집하지 않음"이 기본값 — 근거가 확인되어야 켠다 |
| 6 | 미성년자 연령 기준·보호자 동의 | 단지 거주 가족 단위 서비스라 실제로 발생한다 |
| 7 | 삭제·열람권 처리 기한 | 기한이 정해지면 운영 SLA로 들어가야 한다 |
| 8 | 현지 대리인·DPO 지정 의무 | 조직 구성 문제라 리드타임이 길다 |

> **2번은 리스크가 크다.** 국외 이전 위반은 **직전 연도 매출의 최대 5%** 수준의 제재가
> 거론된다(자문 확인 필요). 스택(Supabase 리전)을 확정하기 **전에** 답을 받는 편이 안전하다.
