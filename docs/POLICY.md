# M4U 제품 정책 (확정본)

> 이 문서의 정책은 코드보다 우선한다. 개정은 대표 승인 후에만 가능하며, 개정 시 CR_LOG에 기록한다.
> 모든 수치는 데모 자리표시자이며, 단위 경제 검증 후 확정한다. (수치 ≠ 정책. 원칙이 정책이다.)

## 1. Consumer First Ranking

- 순위 요소: 별점(Verified) · 재이용률 · 예약 이행률 · 취소율(감점) · 응답 속도 · 소비자 Reward 환원
- **광고비·플랫폼 납부액은 어떤 경우에도 순위에 반영하지 않는다.**
- 신규 파트너는 discovery boost로 최소 노출 보장(목록 2번째 위치), 실이용 리뷰 확보 시까지.
- 파트너에게는 순위 개선을 "광고 구매"가 아니라 "서비스 개선"으로 안내한다.
- **FEED 활성도(언급량·좋아요 수·팔로워 수·게시 빈도)와 FIVE 개설·판매량은 순위 요소가 아니다.** 파트너 자신의 게시물 지표도 반영하지 않는다 (§11).

## 2. Verified Review

- 실제 M4U 예약·결제 이용자만 작성 가능.
- 보상은 **좋은 별점이 아니라 성실한 작성**에 지급 (+5CP).
- 이상 탐지: 동일 기기/IP 반복, 미이용 계정 작성 시도, 단시간 대량 작성 → Admin 플래그.
- FEED의 `M4U 이용 확인` 표시는 예약·결제 기록에 근거한 **이용 사실 표시**이며 Verified Review가 아니다. 별점이 없고 공식 평점·Consumer First Ranking에 반영되지 않는다 (§11.4).

## 3. HRP — HARU REWARD POINT

- 결제·적립용 리워드 포인트. Living·Habit·Salon 전 영역의 보상이 하나의 지갑으로 모인다.
- 발행·소각은 Admin SUPER 권한 + 2인 승인(4-eyes) + 감사 로그.
- 추후 유틸리티 토큰 전환 대상이나, **현 단계 사용자 노출 문구에 코인/토큰 표현 금지** (베트남·한국 규제 대응). Web2 구조로 운영 후 온체인 1:1 이관 전제.

## 4. CP — 기여 포인트

- 양도·구매·수동 발행 **불가**. 검증 가능한 활동에만 규칙 기반 자동 적립.
- 적립 예: Verified 리뷰 +5, FIVE 참여 +10, 예약 이행 +3, 스테이 완료 +5, 파트너 승인 +50, 걷기 목표(헬스 데이터 검증) +2.
- 용도: 커뮤니티 투표 가중치. 추후 SBT/온체인 거버넌스로 동일 구조 이관.
- **FEED 게시는 CP 적립 대상이 아니다** (§11.6).

## 5. Habit 보상

- 검증형(헬스 데이터 연동: 걷기 등)만 CP 지급. 셀프 체크는 소액 HRP + 일일 상한(15 HRP), 하루 1회·해제 불가.
- 습관은 지역 시설과 연결한다 (명상 → 주변 명상 장소 예약 → 지역 소비 → Verified Review).
- 의료성 표현 금지: "피부 진단" → "피부 분석 / 뷰티 프로필". 뷰티 프로필 화면에 "의료 진단이 아님"을 명시.
- Habit 완료 기록은 FEED에 공유될 수 있다. 이때 HRP는 **습관 완료에 대한 보상**이며 게시에 대한 보상이 아니다 (§11.6).

## 6. M4U FIVE 공동구매

- 5/10/15인 방, 할인 40/45/50%, 보상 HRP 20/40/60, 모집 72/96/120시간.
- 보상은 **구매 건수 비례** (인원 모집 비례 금지). 이는 관련 법적 리스크를 낮추기 위한 내부 원칙이며, **실제 운영 전 법률 검토가 필요하다.**
- 미달 시 자동 취소 + 전액 환불. 이 문구를 참여 화면에 항상 노출.

### 6.1 개설 주체

- FIVE 공동구매는 **M4U 본사** 또는 **승인된 브랜드·파트너**가 개설할 수 있다.
- 브랜드 개설은 **§8의 파트너 승인 절차**를 거친 주체만 가능하며, Admin이 상품·가격·재고를 사전 검수한다.
- 개설 주체를 참여 화면에 **항상 표시**한다 (M4U 공식 / 브랜드명).

### 6.2 보상 재원과 산정 (절대 규칙)

- **사람을 모집한 숫자 자체에 따라 금전·HRP를 지급하는 구조는 만들지 않는다.**
- 보상은 **실제 구매·실제 거래·검증된 기여**를 기준으로만 산정한다.
- 참여자를 데려온 대가로 지급하는 추천 보상은 **1단계로 한정**한다 (§7·§10과 동일).
- 브랜드 개설 방의 HRP 재원은 **브랜드 부담**을 원칙으로 하되, 부담 주체를 Admin 정산에 분리 기록한다.

### 6.3 랭킹 분리 (절대 규칙)

- FIVE 개설·개설 횟수·판매량은 **사업자·매장의 Consumer First Ranking에 반영하지 않는다** (§1).
- **FIVE 내부의 상품 정렬(인기·마감 임박 등)은 이 제한과 무관하게 운영할 수 있다.**
- 브랜드가 개설료·수수료를 부담하더라도 그것이 **사업자 노출·순위로 이어지지 않는다.**

### 6.4 tier와 가격

- 방 구조(5/10/15인)와 모집 시간(72/96/120시간), **미달 시 자동 취소·전액 환불**은 개설 주체와 무관하게 동일하다.
- 상품 원가와 재고는 브랜드가 제시하고 Admin이 검수한다.
- 할인율 **40/45/50%는 현재 파일럿 운영 기준값이며, 상품별 단위경제 검증과 대표 승인에 따라 조정할 수 있다.**

## 7. Host 보상 (숙소 제공자)

- Host = M4U 생활권 유입 파트너. 객실별 Guest QR로 귀속 (ROOM → HOST).
- **3원칙 (절대 규칙)**
  1. **1단계 추천 보상만** — Host가 다른 Host를 모집해 수익을 얻는 구조 금지 (다단계 방지).
  2. **귀속 한정** — 체크인~체크아웃 기간만 귀속, Host 본인 계정 결제는 보상 제외.
  3. **프라이버시** — Host에게 투숙객 개별 결제 내역 비노출. 집계 수치·카테고리만 제공.
- 보상률(예시 2%)·수수료 배분은 업종별 마진과 베트남 현지 규정 검증 후 확정.
- 개인 Host 지급 시 베트남 원천징수 처리.
- M4U Recommended Stay 등급은 이용률·만족도 기반 — 돈으로 살 수 없다.

## 8. 파트너 모드

- 앱 분리 없음: M4U 하나 + 파트너 모드. 하나의 계정 · 하나의 지갑.
- 역할: 로컬 비즈니스 / SALON / MOBILITY / HOST — MY BUSINESS 화면은 역할별로 자동 구성.
- 등록: AI 대화 → 구조화 초안 → 필수 확인 3종(사업자·위치·업종 서류) → Admin 승인 → MY BUSINESS 생성 +50CP.
- 본사 운영은 별도 Admin Web (소비자 앱에 관리 기능 미노출).

## 9. 표기 규칙

- HRP 정식 명칭: **HARU REWARD POINT**.
- 단지명: **빈홈 그랜드 파크 / Vinhomes Grand Park** ("비노" 금지).
- 이중언어: 사용자 노출 문자열은 한국어/베트남어 모두 제공 (`L(lang, ko, vi)`).

## 10. M4U Contributor (기여자 네트워크)

- 모든 파트너는 Contributor — 고유 QR(Room/Table/Counter/Mirror/Vehicle/Class QR 등)이 M4U의 오프라인 유입 채널이 된다.
- **보상 2분리 (절대 규칙)**
  - ① Transaction Reward: 직접 거래를 만든 것에 대한 제휴 보상 (예: Host 객실 QR → Spa 예약).
  - ② Ecosystem Contribution Reward: M4U 성장 기여 보상 — **검증된 행동**(신규 가입 → 첫 실제 이용 → Verified Review)에만 적립.
- **랭킹 방화벽**: 기여점수(Contribution Score)는 Consumer First Ranking과 검색 품질에 **절대 반영하지 않는다**. 노출 혜택은 Contributor 배지와 별도 Contributor 섹션 노출로 한정한다.
- **시효**: 유입 기여 기록은 영구 보존하되, 보상은 가입 후 90일 내 검증 활동까지만 적용한다(수치는 데모 — 재무 검증 후 확정).
- **1단계 한정**: 유입 보상도 다단계 구조 금지. 자기 유입(본인·직원 계정)은 자동 제외.
- **재원**: Ecosystem 보상의 재원은 거래 수수료가 아니라 마케팅 예산(광고비 대체)이며, 1인당 보상 상한은 예상 LTV 기준으로 설정한다. 현금성 지급 시 원천징수 처리.
- **장부 분리**: 소비자 CP와 파트너 Contribution Score는 철학(검증된 기여만·구매 불가)을 공유하되 장부를 분리한다 — 커뮤니티 투표 가중치에 사업자 기여 혼입 금지.
- 혜택 4종: 기여 보상 · 배지/별도 노출 · 사업 도구(프로모션·AI Manager·고객 분석 등급제) · 거버넌스 기여는 Web3 단계에서 검토.

## 11. 커뮤니티 / FEED

### 11.1 목적

- FEED는 생활권 이웃이 **지역 생활·습관·맛집·Salon·체험·FIVE 공동구매를 발견하고 공유**하는 공간이다.
- 목적은 평가가 아니라 **발견과 공유**다. 평가의 공식 창구는 Verified Review(§2)다.

### 11.2 게시 주체와 범위

- **누구나 게시할 수 있다.** 실제 이용 여부는 게시 조건이 아니다.
- 지역 맛집, 생활정보, Salon, 운동·명상 장소, 체험, Habit 기록, FIVE 발견을 자유롭게 다룰 수 있다.

### 11.3 공식 평점과의 분리 (절대 규칙)

- FEED 게시물의 내용·표현·인기도는 **매장 공식 평점에 반영하지 않는다.**
- 공식 평점에 반영되는 것은 **Verified Review(§2)뿐**이다.
- FEED에는 **별점 입력 UI를 두지 않는다.**

### 11.4 `M4U 이용 확인` 표시

- M4U 예약·결제 기록이 있는 이용자가 해당 장소를 언급해 게시하면 **`M4U 이용 확인`**(vi: `Đã xác nhận sử dụng M4U`) 표시를 붙일 수 있다.
- 의미는 **"M4U 예약·결제 기록으로 해당 장소 이용 사실이 확인됨"까지만**이다.
- **별점 없음 · 공식 Review 아님 · 공식 평점 미반영 · Consumer First Ranking 미반영.**
- **`Verified`라는 단어를 이 표시에 사용하지 않는다** — Verified Review와의 혼동을 구조적으로 차단한다.

### 11.5 랭킹 방화벽 (절대 규칙)

- **FEED 언급량·좋아요 수·팔로워 수·게시 빈도는 Consumer First Ranking과 사업자·매장·서비스의 공식 검색/추천 순위에 반영하지 않는다.**
- FEED에서 인기가 많다는 이유로 매장 순위가 오르지 않는다.
- **FEED 내부의 콘텐츠 정렬·추천(최신성·관련성·인기글 등)은 이 제한과 무관하게 운영할 수 있다.** 다만 그 결과가 사업자 공식 순위로 이어지지 않는다.
- 파트너 노출 혜택은 **FEED 내부 섹션**으로 한정한다 (§10 Contributor와 동일 구조).

### 11.6 보상 — FEED는 보상 채굴 수단이 아니다 (절대 규칙)

- **게시 행위 자체에는 HRP를 자동 지급하지 않는다.** 맛집 소개·생활정보·Salon 소개·사진 게시는 **커뮤니티 참여 기능이며 무보상**이다.
- HRP는 아래 **확인 가능한 행동**에서만 발생하고, FEED는 그 행동의 기록이 공유되는 곳이다.
  1. **Habit 완료 기록** (§5)
  2. **M4U 실제 예약·결제 이용** (§3)
  3. **정책에서 별도로 승인한 캠페인**
- 설계 원칙: `글을 써서 HRP를 받는다`(X) → **`실제 행동을 하고 그 기록이 FEED에도 남는다`(O)**
- 좋아요·팔로워·조회수에 비례한 보상은 만들지 않는다.
- **FEED 게시는 CP 적립 대상이 아니다** (§4).

### 11.7 파트너 게시물

- 식당·Salon·Host·Mobility·브랜드 등 파트너가 **자기 서비스를 소개하는 것을 허용한다.**
- 단, 다음을 지킨다.
  - **`PARTNER` 또는 `공식 파트너` 표시를 반드시 붙인다.**
  - **일반 사용자 게시물처럼 위장하는 것을 금지한다** (대가성 대리 게시 포함).
  - **자기 게시물의 좋아요·언급량은 Ranking에 반영하지 않는다.**
- **파트너 공식 Ranking은 §1의 Consumer First Ranking 기준에 따라 산정하며, FEED 지표·광고비·게시 빈도는 반영하지 않는다.**

### 11.8 모더레이션

- 모든 게시물·댓글에 **신고** 기능을 제공한다.
- 이용자는 특정 계정을 **차단**할 수 있고, 본인 게시물을 **삭제**할 수 있다.
- Admin은 신고 누적·법령 위반·허위 정보 게시물을 **비공개 처리**할 수 있으며 사유를 기록한다.
- 베트남 현지 온라인 콘텐츠 규정을 준수한다.

### 11.9 어뷰징 방지

- 단시간 대량 게시, 자기 홍보 반복, 대가성 게시는 Admin 플래그 대상이다.
- 어뷰징 판별에 **기술적 신호를 활용할 수 있다.** 다만 **어떤 식별정보를 수집·보관할지는 별도 Privacy/Abuse Spec에서 정하며, 현지 개인정보 법률 검토를 거친다.**
- 자기 유입·자기 홍보는 어떤 지표에도 산입하지 않는다 (§10과 동일).

### 11.10 확장

- FEED는 Habit 기록에서 출발해 맛집·생활정보·Salon·체험·FIVE 발견으로 확장한다.
- 확장 시에도 **§11.3 · §11.5 · §11.6** 세 절대 규칙은 예외 없이 적용한다.
