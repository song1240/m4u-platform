# M4U Design System — MASTER UI 기준

> **단일 기준**: `src/master-ui/` (MasterUI.jsx + style.css)가 공식 디자인 기준이다.
> **핵심 규칙**: 이후 모든 화면은 마스터 UI의 컴포넌트와 CSS 클래스를 **재사용**한다.
> 독자적으로 재디자인하지 않는다. 새 패턴이 필요하면 먼저 이 문서와 style.css에 추가한 뒤 사용한다.
> 코드 토큰: `src/tokens/design-tokens.js` — 이 문서·style.css와 항상 동기 유지.

## 1. 브랜드 톤

**Forest × Ivory × Champagne Gold.** 프리미엄 컨시어지의 신뢰감.
헤드라인은 세리프(DM Serif Display)로 품격을, 본문은 Inter로 실용성을.
배경은 아이보리 — 순백·순흑 금지.

## 2. 컬러 (CSS 변수 = style.css `:root`)

| 변수 | 값 | 용도 |
|---|---|---|
| `--g` forest | `#073B2B` | Primary — 헤더 배경, CTA, 네비 활성, 다크 카드(.ai/.wallet) |
| `--g2` forest2 | `#0E533C` | 진행바, 긍정 수치, 타일 아이콘 |
| `--gold` | `#C6A15B` | 라벨(em/small), 강조, 아바타 텍스트 — 면적 최소로 |
| `--iv` ivory | `#F7F3EA` | 앱(셸) 배경 |
| `--p` paper | `#FFFDF8` | 카드·타일·네비 배경 |
| `--line` | `#E8E0D4` | 보더 |

규칙: 골드는 라벨·강조에만(면적 10% 미만). 다크(forest) 카드류는 화면당 1~2개.
색상 하드코딩 금지 — 반드시 CSS 변수 사용.

## 3. 타이포그래피

- **DM Serif Display (400)**: `header h1`(30px)·`.section`(19px)·큰 수치(`.hero strong` 34px, `.wallet h1` 29px)·아바타. 이탤릭·굵기 변형 금지.
- **Inter**: 본문 12px · 캡션 11px · 타일 10px. 굵기 400/600/700/800.
- **골드 라벨**(`em`, `header small`): 10px / 800 / letter-spacing 1px / 대문자 영문 권장 (예: `MY DAY`, `AI PICK`).

### 4.1 온보딩 다크 캔버스 (H06 ①)

앱 진입 **전** 3화면(언어 → 소개 → MY ZONE)에만 쓰는 forest 풀블리드 캔버스.
진입 후 화면은 아이보리 기준이며 이 패턴을 사용하지 않는다.

| 클래스 | 용도 |
|---|---|
| `.shell.solo` + `.onboard` | 하단 네비 없는 풀블리드 forest 그라데이션 화면 |
| `.brandmark` | M4U(세리프 40, 골드) + LIVING(레터스페이싱 6) 워드마크 |
| `.obtop` / `.back` / `.dots` | 상단 바 — 뒤로가기 + 3단계 진행 표시 (활성 = 골드 바) |
| `.mid` / `.obfoot` | 본문(수직 중앙) / 하단 CTA 영역 |
| `.opts` > `.opt`(`.on`) | 다크 캔버스 선택 리스트 — 선택 시 골드 보더 + 골드 체크 |
| `.values` | 3열 가치 소개 (원형 골드 아이콘 + 제목 + 캡션) |
| `.primary.gold` | 골드 CTA — **다크 캔버스 전용** |
| `.ghost` | 보조 텍스트 버튼 (둘러보기 등) |

- 골드 CTA는 forest 배경에서 대비를 확보하기 위한 예외다. 아이보리 화면의 주 CTA는 기본 forest `.primary` (§2 골드 면적 규칙 유지).
- 다크 캔버스의 보조 색은 흰색 알파 오버레이만 사용한다 (`design-tokens.js`의 `overlay`).

### 4.2 프로덕션 홈 패턴 (홈 리디자인 — 레퍼런스: M4U 프리미엄 목업)

홈은 "포스터"가 아니라 "도구"다 — 큰 forest 헤더(`<Head>`) 대신 컴팩트 앱바 + 사진 중심 콘텐츠.
서체 위계: 세리프는 로고타입·섹션 제목·퍼센트 수치에만, 인사말·본문은 Inter.
**홈 전용 패턴이며 다른 화면은 기존 `<Head>` 유지** (이관 여부는 화면별 하네스에서 결정).

| 클래스 | 용도 |
|---|---|
| `.appbar` | 스티키 상단바 — 세리프 로고타입(M4U/LIVING) + MY ZONE 칩, 아이보리 블러 |
| `.logotype` / `.zonechip` / `.hrpchip` | 워드마크 · 생활권 칩 · HRP 잔액 칩(골드 M 모노그램) |
| `.greet` | 인사말 행 — Inter 800 20px + 보조문 + 우측 HRP 칩 |
| `.mrow` | 컴팩트 지표 행 (아이콘 + 제목 + 진행바 + 세리프 % + 셰브런) — MY DAY |
| `.qrow` > `.q` | 4열 퀵엔트리 (54px 라운드 아이콘 + 라벨, 카드 박스 없음) |
| `.promo` | 포토 프로모 배너 — forest 그라데이션 + 우측 실사, 골드 미니 CTA |
| `.sechead` + `.seeall` | 섹션 헤더(세리프) + "전체보기" 텍스트 버튼 |
| `.bene` | 혜택 카드 — 상단 실사 72px + 본문 (2열) |
| `.hscroll` > `.shopcard` | 가로 스크롤 상점 카드 — 실사 98px + 리워드 배지 + 이름/평점/도보 |
| `.ai.slim` | AI 컨시어지 슬림 바 (기존 `.ai`의 컴팩트 변형) |

- 실사 규칙(§7)대로 사진은 반드시 실사, 텍스트 위엔 다크 그라데이션.
- 사진은 `<img>` + CSS `object-fit`으로 넣는다 (인라인 background 스타일 금지 유지).
- 터치 피드백: 홈 v2 인터랙티브 요소는 `:active` 시 투명도 피드백.

### 4.3 Living 패턴 — 목록 · 상세 · 예약 (H06 ③)

§4.2의 홈 패턴을 이어받는 콘텐츠 화면군. 서브 화면(카테고리·상세·예약)은 전체 화면 전환으로 쌓고
하단 네비는 유지한다. 사진은 §4.2와 동일하게 `<img>` + `object-fit`.

| 클래스 | 용도 |
|---|---|
| `.subhead` | 서브 화면 상단 바 — 스티키 아이보리, 뒤로 버튼(44×44) + 제목 |
| `.grid.g3` | 3열 타일 그리드 — Living 6카테고리 전용(기본은 4열, §5) |
| `.prow` | 사진 리스트 행 — 62px 실사 + 본문 + 셰브런 (랭킹·카테고리 목록의 기본 행) |
| `.tag` (`.ok`/`.new`/`.rank`/`.st`) | 뱃지 — Verified · 신규 부스트 · 순위 · 상태 |
| `.note` | 정책 고지 카드 — 방패 아이콘 + 본문 (광고비 미반영·Verified 조건 상시 노출) |
| `.dhero` | 상세 히어로 — 실사 + 상단 그라데이션 + 플로팅 원형 버튼(`.fabr`) + 로고 원(`.logomark`) |
| `.segs` | 세그먼트 탭 — 서비스/리뷰/정보, 활성만 forest 언더라인 |
| `.feats` | 특징 4열 스트립 (비인터랙티브 정보) |
| `.srow` + `.btn-sm` | 서비스 행 + 우측 소형 CTA (행 자체는 비클릭) |
| `.chips` > `.chip`(`.on`/`:disabled`) | 선택 칩 — 서비스·날짜·시간. 마감은 색+취소선 병행(§7) |
| `.section.sm` | 폼 필드 라벨 — 세리프 섹션 제목 대신 Inter 800 13px (예약 폼) |
| `.spec` > `.r`(`.total`) | 명세행 — 결제·적립 내역 |
| `.ctabar` | 하단 고정 CTA — nav(72px) 위, 상단 아이보리 페이드 |
| `.sheetbd` + `.sheet` | 바텀시트 — 확인 다이얼로그. 셸 폭(430px)에 정렬 |
| `.toast` | 하단 알림 pill — 적립 결과 등 피드백 (2.2초) |
| `.done` | 완료 패널 — 체크 원 + 적립 결과(`.earn`, forest2 — 골드 금지) |
| `.empty` | 빈 상태 — "준비 중" 안내 (특정 파트너 홍보 금지) |

- 뱃지·적립 강조에 골드를 쓰지 않는다 — 골드는 라벨 전용(§2 면적 규칙). 적립 수치는 `--g2`.
- 신규 파트너 `.tag.new`는 **목록 2번째 위치** 고정 (POLICY §1).
- v10의 9~10px 캡션을 그대로 옮기지 않는다 — muted 최소 11px(§7).

### 4.4 Habit 패턴 — 습관 실행 (H06 ④)

검증형(헬스 데이터)과 셀프 체크를 **시각적으로 구분**한다 — 검증형만 Verified 뱃지와 CP를 받는다 (POLICY §5).
셀프 체크는 하루 1회·해제 불가이며 일일 HRP 상한이 있으므로, 상한 도달 상태를 화면에 명시한다.

| 클래스 | 용도 |
|---|---|
| `.hrow` | 습관 행 — 원형 아이콘 + 본문(진행 상태) + 우측 액션(`.btn-sm` 또는 `.chk`) |
| `.hrow.done` | 완료된 습관 — 배경 톤 다운 + 액션 비활성 (해제 불가를 시각화) |
| `.chk` (`.on`) | 셀프 체크 원형 버튼 — 40×40, 완료 시 forest2 채움 + 흰 체크 |
| `.gauge` > `i` | 칸 게이지 (물 8잔) — 채워진 칸만 forest2 |
| `.wchart` > `div` | 주간 막대 — 오늘은 골드, 목표 달성일은 forest2, 미달은 line |
| `.streak` | 연속 달성 칩 — 앱바 우측(`.zonechip` 변형, 불꽃 아이콘) |

- 검증형 습관에만 `.tag.ok`(헬스 데이터 검증)와 CP 표기를 붙인다. 셀프 체크에는 절대 CP를 표기하지 않는다.
- 일일 상한 도달 시 셀프 체크는 계속 가능하되 **HRP 0 적립**으로 처리하고 `.note`로 사유를 안내한다.

## 5. 레이아웃

- 셸 최대폭 430px 중앙 정렬, 700px 이상에서 radius 32 카드형.
- 페이지 좌우 패딩 16px. 카드 간격 9px. 네비 높이 72px(하단 여백 82px 확보).
- 그리드 타일은 4열 고정.

## 6. 언어·문구 (POLICY §9 준용)

- 사용자 노출 문자열은 `L(lang, ko, vi)` 경유 (마스터 UI는 이식 시(H06) 적용).
- 금지: "피부 진단"(→ 피부 분석/뷰티 프로필), 사용자 노출 "코인/토큰", "비노 그랜드".
- 베트남어는 한국어보다 20~40% 길다 — 타일·버튼 줄바꿈 허용.

## 7. 이미지·접근성

- 실사 사진만(일러스트 금지). `.salonhero` 패턴처럼 다크 그라데이션 오버레이로 텍스트 가독성 확보.
- 터치 타깃 최소 40×40 · muted 텍스트 11px 미만 금지 · 색+아이콘/텍스트 병행 표기.

## 8. 레거시

- `src/App.jsx`(v10)와 `src/admin/Admin.jsx`는 **이전 디자인(인라인 스타일)** — 기능·플로우 참조용.
- 신규 작업에서 v10의 인라인 스타일 복사 금지. 기능만 가져오고 표현은 마스터 UI 패턴으로 (H06).
