# M4U Design System — MASTER UI 기준

> **단일 기준**: `src/master-ui/` (MasterUI.jsx + style.css)가 공식 디자인 기준이다.
> **핵심 규칙**: 이후 모든 화면은 마스터 UI의 컴포넌트와 CSS 클래스를 **재사용**한다.
> 독자적으로 재디자인하지 않는다. 새 패턴이 필요하면 먼저 이 문서와 style.css에 추가한 뒤 사용한다.
> 코드 토큰: `src/tokens/design-tokens.js` — 이 문서·style.css와 항상 동기 유지.

## 1. 브랜드 톤

**Forest × Ivory × Champagne Gold.** 프리미엄 컨시어지의 신뢰감.
헤드라인은 세리프(DM Serif Display)로 품격을, 본문은 Inter로 실용성을.
배경은 아이보리 — 순백·순흑 금지.

## 3. 타이포그래피

- **DM Serif Display (400)**: `header h1`(30px)·`.section`(19px)·큰 수치(`.hero strong` 34px, `.wallet h1` 29px)·아바타. 이탤릭·굵기 변형 금지.
- **Inter**: 본문 12px · 캡션 11px · 타일 10px. 굵기 400/600/700/800.
- **골드 라벨**(`em`, `header small`): 10px / 800 / letter-spacing 1px / 대문자 영문 권장 (예: `MY DAY`, `AI PICK`).

### 4.1 온보딩 다크 캔버스 (H06 ①)

앱 진입 **전** 3화면(언어 → 소개 → MY ZONE)에만 쓰는 forest 풀블리드 캔버스.
진입 후 화면은 아이보리 기준이며 이 패턴을 사용하지 않는다.

| 클래스 | 용도 |
|---|---|
| `.shell.solo` + `.onboard` | 하단 네비 없는 풀블리드 forest 그라데이션 화면 |
| `.brandmark` | M4U(세리프 40, 골드) + LIVING(레터스페이싱 6) 워드마크 |
| `.obtop` / `.back` / `.dots` | 상단 바 — 뒤로가기 + 3단계 진행 표시 (활성 = 골드 바) |
| `.mid` / `.obfoot` | 본문(수직 중앙) / 하단 CTA 영역 |
| `.opts` > `.opt`(`.on`) | 다크 캔버스 선택 리스트 — 선택 시 골드 보더 + 골드 체크 |
| `.values` | 3열 가치 소개 (원형 골드 아이콘 + 제목 + 캡션) |
| `.primary.gold` | 골드 CTA — **다크 캔버스 전용** |
| `.ghost` | 보조 텍스트 버튼 (둘러보기 등) |

- 골드 CTA는 forest 배경에서 대비를 확보하기 위한 예외다. 아이보리 화면의 주 CTA는 기본 forest `.primary` (§2 골드 면적 규칙 유지).
- 다크 캔버스의 보조 색은 흰색 알파 오버레이만 사용한다 (`design-tokens.js`의 `overlay`).

### 4.2 프로덕션 홈 패턴 (홈 리디자인 — 레퍼런스: M4U 프리미엄 목업)

홈은 "포스터"가 아니라 "도구"다 — 큰 forest 헤더(`<Head>`) 대신 컴팩트 앱바 + 사진 중심 콘텐츠.
서체 위계: 세리프는 로고타입·섹션 제목·퍼센트 수치에만, 인사말·본문은 Inter.
**홈 전용 패턴이며 다른 화면은 기존 `<Head>` 유지** (이관 여부는 화면별 하네스에서 결정).

| 클래스 | 용도 |
|---|---|
| `.appbar` | 스티키 상단바 — 세리프 로고타입(M4U/LIVING) + MY ZONE 칩, 아이보리 블러 |
| `.logotype` / `.zonechip` / `.hrpchip` | 워드마크 · 생활권 칩 · HRP 잔액 칩(골드 M 모노그램) |
| `.greet` | 인사말 행 — Inter 800 20px + 보조문 + 우측 HRP 칩. 인사말은 **생활권 시간(ICT)** 기준 4구간 |
| `.mrow` | 컴팩트 지표 행 (아이콘 + 제목 + 진행바 + 세리프 % + 셰브런) — MY DAY |
| `.qrow` > `.q` | 4열 퀵엔트리 (54px 라운드 아이콘 + 라벨, 카드 박스 없음) |
| `.promo` | 포토 프로모 배너 — forest 그라데이션 + 우측 실사, 골드 미니 CTA |
| `.sechead` + `.seeall` | 섹션 헤더(세리프) + "전체보기" 텍스트 버튼 |
| `.bene` | 혜택 카드 — 상단 실사 72px + 본문 (2열) |
| `.hscroll` > `.shopcard` | 가로 스크롤 상점 카드 — 실사 98px + 리워드 배지 + 이름/평점/도보 |
| `.ai.slim` | AI 컨시어지 슬림 바 (기존 `.ai`의 컴팩트 변형) |

- 실사 규칙(§7)대로 사진은 반드시 실사, 텍스트 위엔 다크 그라데이션.
- 사진은 `<img>` + CSS `object-fit`으로 넣는다 (인라인 background 스타일 금지 유지).
- 터치 피드백: 홈 v2 인터랙티브 요소는 `:active` 시 투명도 피드백.

하단 네비는 유지한다. 사진은 §4.2와 동일하게 `<img>` + `object-fit`.

| 클래스 | 용도 |

| `.grid.g3` | 3열 타일 그리드 — Living 6카테고리 전용(기본은 4열, §5) |

| `.segs` | 세그먼트 탭 — 서비스/리뷰/정보, 활성만 forest 언더라인 |

### 4.4 Habit 패턴 — 습관 실행 (H06 ④)

검증형(헬스 데이터)과 셀프 체크를 **시각적으로 구분**한다 — 검증형만 Verified 뱃지와 CP를 받는다 (POLICY §5).
셀프 체크는 하루 1회·해제 불가이며 일일 HRP 상한이 있으므로, 상한 도달 상태를 화면에 명시한다.

| 클래스 | 용도 |
|---|---|
| `.hrow` | 습관 행 — 원형 아이콘 + 본문(진행 상태) + 우측 액션(`.btn-sm` 또는 `.chk`) |
| `.hrow.done` | 완료된 습관 — 배경 톤 다운 + 액션 비활성 (해제 불가를 시각화) |
| `.chk` (`.on`) | 셀프 체크 원형 버튼 — 40×40, 완료 시 forest2 채움 + 흰 체크 |
| `.tag.off` / `.tag.self` | 미연동(회색) · 자기 신고(회색) — 검증형 `.tag.ok`와 구분 |
| `.linkcard` | 건강 앱 연결 카드 — 미연동 시 걷기 행 위에 노출 |
| `.gauge` > `i` | 칸 게이지 (물 8잔) — 채워진 칸만 forest2 |
| `.wchart` > `div` | 주간 막대 — 오늘은 골드, 목표 달성일은 forest2, 미달은 line |
| `.streak` | 연속 달성 칩 — 앱바 우측(`.zonechip` 변형, 불꽃 아이콘) |

- 검증형 습관에만 `.tag.ok`(헬스 데이터 검증)와 CP 표기를 붙인다. 셀프 체크에는 절대 CP를 표기하지 않는다.
- **검증 뱃지는 실제 연동 상태일 때만 붙인다.** 건강 앱 미연동이면 `.tag.off`(미연동)를 붙이고
  목표를 채워도 **HRP만** 지급한다 — 연동 없이 CP를 주면 "검증 가능한 활동" 원칙이 깨진다 (POLICY §4).
- 셀프 체크 행에는 `.tag.self`(자기 신고)를 붙여 검증형과 **한눈에 구분**되게 한다.
- 일일 상한 도달 시 셀프 체크는 계속 가능하되 **HRP 0 적립**으로 처리하고 `.note`로 사유를 안내한다.

### 4.5 Salon 패턴 — 뷰티 프로필 (H06 ⑤)

**의료성 표현 절대 금지** (POLICY §5). "피부 진단" 대신 **"피부 분석 / 뷰티 프로필"**만 쓰고,
설문·결과 화면 최상단에 "의료 진단이 아님"을 `.note`로 **항상** 노출한다.

| 클래스 | 용도 |
|---|---|
| `.card.accent` | 골드 보더 강조 카드 — 뷰티 프로필 진입·결과 (화면당 1~2개) |
| `.chips.col` > `.chip` | 세로 선택 리스트 — 설문 보기(좌측 정렬, 선택 시 forest) |
| `.metrics` > `div` | 프로필 지표 3열 — 라벨 + % + 진행바(`.bar`) |
| `.rvcard` | Verified Review 카드 — 작성자 + 인증 뱃지 + 별점 + 본문 |

- 결과 수치(수분·유분·진정)는 설문 응답으로 계산하되 **데모 자리표시자**임을 유지한다.
- 추천은 "MY ZONE · 뷰티 프로필 · Verified Review 기반"으로만 설명한다 — 광고 노출 아님 (POLICY §1).

### 4.6 지갑 패턴 — HRP · CP · FIVE (H06 ⑥)

HRP(결제·적립)와 CP(기여·투표 가중치)는 **성격이 다르므로 한 카드 안에서 좌우로 분리**해 보여준다.
CP는 구매·양도가 불가능하다는 사실을 자산 카드에 **항상** 명시한다 (POLICY §4).
FIVE 참여 화면에는 "구매 건수 비례 보상 · 미달 시 자동 취소 및 전액 환불"을 **항상** 노출한다 (POLICY §6).

| 클래스 | 용도 |
|---|---|
| `.wcard` | 자산 다크 카드 — HRP/CP 2분할(`.asset`), 구분선, 하단 정책 문구 |
| `.five` | FIVE 방 카드 — 상품 실사 + 원가 취소선/할인가 + 인원·마감·보상 + 진행바 + 참여 CTA |
| `.coupon` | 쿠폰 행 — 골드 티켓 아이콘 + 제목/조건 + 사용 버튼(사용 시 톤 다운) |
| `.vcard` | 제안 카드 — 제목 + 마감/가결 뱃지 + 찬반 CP + 정족수 진행바 + 찬성/반대 버튼 |
| `.logrow` | 내역 행 — 사유 + 일시 + 증감액(적립 forest2 / 사용 ink) |

- 자산 수치·보상률은 전부 데모 자리표시자 (CLAUDE.md §6).
- HRP를 화폐·자산처럼 부르지 않는다. 코인/토큰 표현 금지 — `verify`의 금지어 스캔이 강제한다.

### 4.7 파트너 · Contributor 패턴 (H06 ⑦ · H07)

파트너 화면도 소비자와 같은 셸·팔레트를 쓴다 — 앱을 분리하지 않는다 (POLICY §8).
HOST 화면은 **집계만** 보여준다. 투숙객 개별 결제 내역을 표시하는 UI를 만들지 않는다 (POLICY §7-3).
Contributor 섹션에는 **랭킹 방화벽**(기여점수는 순위·검색에 미반영)을 항상 명시한다 (POLICY §10).

| 클래스 | 용도 |
|---|---|
| `.steps` | 4단계 진행 표시 — 완료 단계만 forest 원 |

### 4.11 FEED 패턴 — 커뮤니티 (POLICY §11)

**피드는 리뷰가 아니다.** POLICY §2의 Verified Review(실제 예약·결제자만)를 우회하는 채널이 되면 안 되므로:

- 피드 게시물에는 **별점이 없다.** 매장을 언급할 수 있어도 **매장 평점과 사업자 공식 검색/추천 순위에 절대 반영하지 않는다** (POLICY §11.3·§11.5). 피드 안에서의 정렬(최신·관련)은 자유롭다.
- **게시 행위 자체에는 HRP를 주지 않는다** (§11.6). HRP는 Habit 완료(§5)·실제 예약/결제(§3)에서 나오고, 피드는 그 행동의 기록이 공유되는 곳이다.
  → `글을 써서 보상을 받는다`가 아니라 **`행동하고 그 기록이 남는다`**. 맛집·생활정보 게시물이 늘어나도 보상 채굴이 되지 않는다.
- 게시물은 **CP 적립 대상이 아니다** (§4). 사진은 조작 가능하므로 "검증 가능한 활동"이 아니다.
- 습관 완료는 **한 줄 기록을 남겨야** 인정된다 — 탭 한 번보다 강한 근거를 남기게 하는 것이 목적이다. HRP는 그 **습관 완료**에 붙는다(셀프 일일 상한 15 HRP 적용).

| 클래스 | 용도 |
|---|---|
| `.post` | 피드 카드 — 작성자 + 시각 + 습관 뱃지 + 본문 + 선택 사진 |
| `.post .ph` | 첨부 사진 — 라운드 16, `object-fit: cover` |
| `.composer` | 기록 작성 시트 — 습관 라벨 + textarea + 사진 첨부 + 게시 |
| `.pickimg` | 사진 첨부 버튼(라벨) — `input[type=file]`은 숨기고 라벨만 노출 |
| `nav` 6열 | 탭이 6개이므로 아이콘 18 · 라벨 8.5px로 축소 |
| `.writebar` | 글쓰기 진입 — "이웃에게 무엇을 알려줄까요?" |
| `.chip.on` | 선택된 카테고리 필터 (Forest 반전) |

**2단계 — 카테고리와 자유 게시 (§11.2 · §11.6)**

- 카테고리 5종: 습관 · 맛집 · 생활정보 · Salon · 체험. 상단 칩으로 필터한다.
  **피드 내부의 정렬·필터는 §11.5가 명시적으로 허용한다** — 다만 그 결과가 사업자 공식 순위로 이어지지 않는다.
- 글쓰기는 `Composer` 시트 하나로 통일한다.
  - **습관 기록**: 습관을 완료 처리하고 그 습관의 HRP를 지급 (§5)
  - **자유 게시**: 맛집·생활정보 등. **보상 없음** — 쓰기 전에 "이 글에는 적립이 없어요"로 미리 알린다
- 게시 후 토스트도 사실대로 말한다: 자유 게시는 `"이웃에게 공유했어요 (적립 없음)"`.
  **없는 보상을 있는 것처럼 알리지 않는다.**

**2단계 — `M4U 이용 확인` · PARTNER 표시 (§11.4 · §11.7)**

- 자유 게시에는 관련 매장을 태그할 수 있다(`.vchip`, 탭하면 매장 상세로 간다).
- **`M4U 이용 확인` 표시는 예약·결제 기록에서만 나온다.** 사용자가 스스로 붙일 수 없다.
  기록이 없으면 `이용 기록 없음`으로 정직하게 보여준다.
- 이 표시에 **`Verified`라는 단어를 쓰지 않는다** — Verified Review와 혼동되면 §2가 무의미해진다.
  의미는 "이용 사실이 확인됨"까지이고 별점 · 평점 · 순위와 무관하다. 시트와 피드 양쪽에 이 문구를 노출한다.
- 파트너 계정의 글에는 **`PARTNER` 뱃지를 반드시** 붙인다(`.tag.partner`, 샴페인 골드).
  일반 사용자 게시물처럼 보이면 안 된다.

**2단계 — 좋아요 · 댓글 (§11.5 · §11.6)**

- `.acts` 좋아요/댓글 버튼, `.cmts` 댓글 목록과 입력.
- **좋아요·댓글에는 보상이 없다.** 수치에 비례한 HRP를 만들면 즉시 어뷰징 유인이 된다.
- **이 수치는 사업자 공식 순위에 들어가지 않는다.** `ranking.js`의 `RANKING_FIELDS`가
  점수에 쓸 수 있는 필드를 명시하고, 여기에 없는 값(FEED 지표·기여점수·광고비)은 넣지 않는다.
  필드를 늘리려면 POLICY §1 개정이 먼저다.

**2단계 — 모더레이션 (§11.8 · §11.9)**

- 게시물마다 `⋯` 메뉴(`.more` → `.modlist` 시트). **내 글은 삭제만, 남의 글은 신고·차단만** 보인다.
- 신고하면 즉시 숨기고 사유를 안내한다. 차단은 작성자 단위이며 **언제든 해제할 수 있다**
  (`.writebar`로 "숨긴 글 n개 · 차단 해제하기" 노출).
- **어떤 식별정보를 수집·보관할지는 화면이 정하지 않는다** — `docs/PRIVACY_ABUSE_SPEC.md`가 정한다.
  프로토타입은 서버가 없으므로 **아무것도 수집하지 않는다.**

**원칙: 모션은 "지금 어디로 이동했는지"를 설명할 때만 쓴다.** 장식용 애니메이션은 넣지 않는다.

- 나가는 모션(exit)은 넣지 않는다. React 언마운트를 붙잡아야 해서 비용 대비 효과가 낮다.

### 7.1 아이콘만 있는 컨트롤 (필수)

**아이콘만 있는 버튼은 스크린리더에 "버튼"으로만 읽힌다.** 무엇을 하는 버튼인지 알 수 없다.

- 텍스트가 없는 모든 버튼에 `aria-label`을 준다. **반드시 `L(lang, ko, vi)`를 거친다** — 보조기술 사용자에게도 이중언어는 동일하게 적용된다.
- 켜짐/꺼짐이 있는 버튼(찜하기·별점)은 `aria-pressed`로 상태까지 알린다.
- 진행바는 `<Bar now max label>`을 쓴다. 막대만 그리면 보조기술에는 아무것도 없는 것과 같다.
- 바텀시트는 `role="dialog"` + `aria-modal` + `aria-label`(제목).
- 토스트는 `role="status"` — 적립·완료를 알리는 유일한 통로이므로 놓치면 안 된다.
- 하단 탭은 현재 탭에 `aria-current="page"`, `<nav>`에는 `aria-label`.

> `aria-label`을 **텍스트가 이미 있는 버튼에 덧붙이지 않는다.** 보이는 글자와 읽히는 이름이 달라지면
> 음성 제어 사용자가 "○○ 눌러줘"라고 말했을 때 동작하지 않는다.
